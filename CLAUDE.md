# imageEditor — floor re-tiling pipeline

Replace the floor in a room photo with a tiled texture while keeping the scene's lighting and shadows.

## Run
```
python floor_edit/floor_edit.py --scene input/scene.jpeg --pattern input/pattern.png            # defaults: --seg ensemble --illum rgbx
python floor_edit/floor_edit.py --scene input/black_tile_flooring.png --seg sam3 --illum heuristic
```
Output: `outputs/floor_edit/<scene>/<pattern>/<seg>/output.jpg` (+ `mask_floor.png`, `illumination.png`, `metrics.json` with per-stage time / GPU peak).
Options: `--seg {ensemble,sam3}`, `--illum {rgbx,heuristic}`, `--tile-m` (texture repeat in metres, 0.6), `--rgbx-steps` (10), `--line-px` (21).

## Layout
- `floor_edit/floor_edit.py` — the whole pipeline in one file (segmentation -> MoGe-2 geometry -> illumination -> plane-fit render).
- `weights/` — `segformer-b5-ade`, `upernet-convnext-l` (ensemble), `sam3`, `moge-2-vitl-normal`, `rgb-to-x` (~11 GB total).
- `repos/MoGe` (`moge.model.v2`), `repos/rgbx` (rgb2x diffusers pipeline) — code dependencies only.
- `ablations/` — result CSVs of all earlier experiments (model survey timings/quality, segmenter comparison, pipeline-v1 stage metrics, illumination-model timings). Everything else from those runs was deleted.
- `input/` — `scene.jpeg` (bedroom 900x1600), `black_tile_flooring.png` (kitchen 1080x1080), `pattern.png` (marble).

## Pipeline
1. **Segmentation** — default: mean-softmax ensemble of SegFormer-B5 + UPerNet ConvNeXt-L (ADE20K, inference 1024x576), floor = {floor, rug}, then 5x5 close + small-component removal. Alternative: SAM 3 with text prompt "floor" (instances > 0.4 unioned). Ensemble has the cleanest boundaries (boundary-F 0.81 vs 0.25 for SAM 3 on the bedroom); SAM 3 is slower and heavier.
2. **Geometry** — MoGe-2 ViT-L point map + intrinsics (fp32; fp16 autocast is broken on XPU).
3. **Illumination** — default RGB->X "Irradiance (diffuse lighting)": **linear RGB in (sRGB^2.2), 10 DDIM steps at 768 px short side, output gamma-decoded (^2.2)** — without this treatment the map is nearly flat. Heuristic = luminance / 90th-percentile floor level.
4. **Render** — least-squares floor plane on the mask's 3-D points (2 inlier re-fits, residual ~0.2 cm), ray/plane intersection -> metric (u,v), texture tiled at `tile_m`, illumination normalised on the floor then grayscale close->open (`line_px`) to drop old grout lines / specks while keeping cast shadows, 2 px blur, composited through a 1 px soft mask.

## Environment
Windows 11, Python 3.13, PyTorch 2.13 XPU (Intel Arc 140T iGPU, 16 GB shared), no CUDA. Typical run: ensemble 4 s, MoGe-2 4 s, RGB->X 9-14 s (incl. first-call warm-up), render 0.3-0.5 s -> ~17-26 s per image excluding model loads.
Constraints: per-file download cap 1 GB (exceptions were granted for SAM 3 3.4 GB and RGB->X 4.9 GB); `facebook/sam3` is gated on this account -> weights came from the `jetjodh/sam3` mirror.

## Gotchas
- Keep GPU runs sequential; the first model call in a process pays 5-15 s of kernel warm-up.
- `weights/*/.cache` may hold stale `.incomplete` downloads from interrupted fetches — delete them.
- Do not spawn subagents for this project.

# object_edit — object move pipeline (OmniPaint default since 2026-09-22; modularised 2026-09-21)
Move the object under `initial` (x,y) so that point lands on `final`. Inputs: image + two points (or boxes) only — no object name is given to any model (user requirement; FreeFine's GeoBench scripts use `guidance_text=""` / `"empty scene"`).
```
python object_edit/object_edit.py --coords input/object_move.json          # kitchen: potted plant (282,440) -> (918,442)
python object_edit/object_edit.py --coords input/object_move_scene.json    # bedroom: chair (170,713) -> (730,714)
python object_edit/object_edit.py --coords ... --removal lama-plain --insertion paste   # ~45 s, no SD
# defaults: --removal omnipaint --insertion omnipaint --omnipaint-mode full --src-region full --dst-region full (~30+ min);
# the fast classic path is --removal lama --insertion freefine --src-region dilated --dst-region dilated (~4 min)
```
Output: `outputs/object_edit/<scene>/output.jpg` (or `--out`) + intermediates + `metrics.json`.
- Package layout: `object_edit.py` (orchestrator `run(task, cfg, out_dir, on_stage)` + CLI), `task.py` (Move/MoveTask/load_task/default_config), `segment.py` (SAM 3 click + clean_mask + dilation), `geometry.py` (MoGe-2 scale), `common.py` (device, Stage, windows), `sd15.py` (shared FreeFine pipeline cache), `removal/` (`lama`, `lama-plain`, `freefine`, `omnipaint`), `insertion/` (`freefine`, `paste`, `omnipaint`), `flux_omnipaint.py` (shared FLUX.1-dev Q8 + OmniPaint LoRA cache; `shared_model="flux"` so removal+insertion load it once). Contracts are in `removal/base.py` and `insertion/base.py`: full-frame uint8 in/out, nothing outside the edited region changes. New backend = one file + one registry line. `run()` unloads the remover before loading the inserter unless both share sd15.
- OmniPaint (repos/OmniPaint, ICCV 2025): FLUX.1-dev + 29 MB LoRA per task, no text (static prompt embeddings in weights/omnipaint/embeddings). Removal condition = scene with the hole blacked out; insertion = that + subject on white with position ids shifted (0,-32). It regenerates the whole 512 canvas and sizes the inserted object to the *mask*, so our modules run it per object in the same ~3x-object windows FreeFine uses, black out the user's **target bounding box** (`move.dst_box`: OmniPaint renders the object to fill it, so the box sets position and size; without a box the depth-scaled paste bbox + 8 px is used; tight silhouettes are ignored) and composite only the hole / box back. In window mode the destination window is re-centred on the box (side = max(512, 3x box)). The conditions the model sees are saved as `obj<i>_condition_*.png` / `removal_condition_*.png`. Base model is the Q8 GGUF (FLUX.1-dev is gated). It runs in a child process (`object_edit/flux_worker.py`, client `flux_omnipaint.py`, PNGs over a temp dir) with **leaf-level group offloading** (< 1 GB resident, ~18 s/step at 512): the 16 GB XPU budget is global across processes (desktop + parent caches count), so a resident 13 GB FLUX OOMs whenever SAM/MoGe ran first; block-level/sequential offload don't work (OmniPaint calls sub-layers directly; accelerate breaks GGUF params). ~9 min per hole, ~12 min per object at 28 steps (`--omnipaint-steps`). `--omnipaint-mode full --omnipaint-res 1024` runs the whole frame instead (long side downscaled to 1024, sides multiples of 16 - OmniPaint's own cap; FLUX is trained ≤ 2 MP): whole-scene context but the fill is upsampled from 1024 and each generation is ~4x the tokens (~25-30+ min at 28 steps); objects must still cover ≥ ~8x8 latent patches (≥ ~130 px on the canvas) or insertion ignores them. Ablation numbers: ablations/last_stage_compare.csv.
- Edit regions are a user choice per stage (`--src-region`, `--dst-region`, each `mask | dilated | box | full`, **default `full`**, `--region-margin` 0.35; UI "Source edit" / "Target edit"). `mask` = the cut-paste baseline (only the silhouette changes, old shadows stay). `dilated` = silhouette grown by margin x object size, biased downwards (`common.shadow_region`), `box` = bbox + margin, `full` = the whole window/frame the model renders. Removers get `region` (>= hole): LaMa/FreeFine-bg fill all of it (they cannot reason about shadows), OmniPaint blacks out only the hole and keeps its re-render inside the region. Inserters composite the region back; FreeFine gets it as `draw_mask` (use_auto_draw=False), OmniPaint keeps that much of its canvas. `full` is downgraded to `box` for non-generative removers (`Remover.generative`).
- Working resolution (`--sr-factor 2|3|4`, UI "Processing resolution"; `object_edit/resolution.py`): after masks/regions/MoGe at native res, the frame + masks are block-averaged by the factor, removal/insertion run on the low-res task, then DDRM super-resolution (deepinv `sampling.DDRM`, DRUNet `weights/dpir/drunet_deepinv_color_finetune_22k.pth`, custom `BlockAverageSR` DecomposablePhysics = blockwise DCT SVD; deepinv's Gaussian `Downsampling` has no SVD so it can't be used with DDRM). Sigmas = `--sr-steps` (15) DDIM timesteps t = k*(1000//n) of the DDPM linear-beta schedule in VE form; eta 0.85, etab 1, seed 0. Only pixels the edit changed (|diff| > 2 on the low-res frame, dilated) are taken from the SR image. Measured: DDRM 20 steps 42 s at 1080^2, 106 s at 2000x1500, ~2.4 GB peak; +1 dB over bicubic (DPIR/HQS gave +3.5 dB in 8 forward passes and remains the better SR - `deepinv.optim.DPIR`, tested in outputs/dpir_sr_test/). `python -m object_edit.resolution --job <dir> --scene <img> --sf N` finishes an interrupted SR.
- Pre-clean (`object_edit/preclean.py`, `DDRMClean`): every scene upload is run through DDRM with the identity operator (noise 0.005 added, 5 DDIM steps t = 800..0, eta 0.85, etab 1) on the GPU worker before SAM encoding; `data/uploads/<id>_clean.png` becomes the working image for masks and both pipelines (`Uploads.path()`), the UI shows a cleaned/original toggle. CLIs: `--preclean`. Finding: with identity + etab 1 the output is within ~0.8/255 of the input regardless of schedule (DDRM re-anchors to y every step), so this stage is close to a no-op; `etab < 1` or an Inpainting physics would be needed for the prior to act. GSPnP (GS-PnP/GSDRUNet) was tried first and removed: 11 s per iteration at 2000x1500 with tens of iterations needed.
- JSON moves accept `src_box`/`dst_box` (centres used) and `mask` (PNG) — this is how the web UI feeds chosen masks; `task.has_masks` skips SAM.
- Stages: SAM 3 one-click mask (best-IoU proposal, upgraded to a < 4x larger one, component under the click) -> MoGe-2 perspective scale z_src/z_dst (`--scale` overrides) -> removal on the full frame (big-lama + Geomagical refiner ~60-95 s, hole = mask dilated 6 px) -> per object: two same-side square windows (~3x object, >= 512) on original/background at 512, affine paste, FreeFine regeneration (`start_step` 15; benchmark 35), composite of target+15 px. ~3-4 min per image on the iGPU (removal + regeneration are ~90 % of it).
- Weights: sam3, moge-2-vitl-normal (shared with floor_edit), stable-diffusion-v1-5 fp16 (2 GB), big-lama (410 MB); omnipaint backends: flux1-dev-gguf (12.7 GB), flux-vae, omnipaint (LoRAs + npz embeddings). Code deps: repos/FreeFine (rembg stubbed; one `.cuda()` patched at runtime), repos/MoGe, repos/lama (its `data.aug` module stubbed; ckpt loaded with weights_only=False).
- Regression note: FreeFine/LaMa-refiner runs are not bit-reproducible on XPU (same seed -> mean |diff| ~2/255); compare visually, not byte-wise.
- Known limits: one click selects one SAM object (the towel on the chair and cast shadows are not in the mask); no shadow synthesis.
- Removed on consolidation (2026-09-19): Depth-Aware-Editing, DragFlow, SH-GAN repos/venvs and their weights. Findings: Depth-Aware-Editing worked (AnyDoor placement, ~15 min, hallucinates small items); DragFlow (FLUX.1-dev) OOMs on the 16 GB iGPU; SH-GAN weights are dead links. `repos/{ARShadowGAN,DIRECT,lama-with-refiner}` and `weights/arshadowgan` are leftovers of later experiments, not used by any pipeline (repos/OmniPaint + weights/{flux1-dev-gguf,flux-vae,omnipaint} are now used by the `omnipaint` backends).
- **Image -> 3D** (`object_edit/image_to_3d.py`, added 2026-09-23): reconstructs a 3D proxy of an object crop with the TRELLIS pipeline that DIRECT (`repos/DIRECT`, ICML 2026) uses, driven as an API - `TrellisImageTo3DPipeline.from_pretrained` -> `get_cond` -> `sample_sparse_structure` -> `sample_slat` -> `decode_slat`, the same call sequence as DIRECT's `demo/demo.py` and `preprocess/preprocess_example.py`. Weights `weights/trellis-image-large` (3.3 GB) + DINOv2 ViT-L via `torch.hub`.
  ```
  python -m object_edit.image_to_3d --image data/jobs/<job>/obj0_subject_512.png
  ```
  Writes `outputs/image_to_3d/<stem>/{input_processed.png, gaussian.ply, mesh.glb, mesh.ply, gaussian_points.ply, preview.png, metrics.json}`. `mesh.ply` + `gaussian_points.ply` are the viewer copies (`--no-viewer-ply` to skip): Open3D imports GLB via ASSIMP and often drops vertex colours, and `gaussian.ply` is the 3DGS splat format (colour as SH DC `f_dc_*`, no `red/green/blue`) so ordinary viewers render it colourless - `gaussian_ply_to_points()` decodes DC->RGB (`0.5 + 0.2820948*f_dc`) and drops splats under 0.1 opacity. Individual splats decode dark (median 25/255) because 3DGS composites many overlapping ones - that is the format, not a bad decode; the mesh is the better view. ~100 s / 10.7 GB peak at the default 512 crop on the iGPU (10 k voxels, 338 k verts). `preview.png` is a 4-view turntable point splat (two-sided lambert - FlexiCubes leaves ~half the vertex normals inward); `mesh.glb` opens in Windows 3D Viewer or gltf-viewer.donmccurdy.com. Not bit-reproducible on XPU like the other stages: the same seed gave 338 371 vs 338 415 verts across runs. Options: `--formats gaussian mesh radiance_field`, `--matte {auto,white,rmbg,none}`, `--mask`, `--ss-steps/--slat-steps/--cfg`, `--save-slat` (DIRECT's `slat.pt`), `--fp32`.
  **Colour - which representation to display.** The mesh decoder's per-vertex colour channel loses ~37 % saturation (measured on `obj0_subject_512.png`: input S 0.248 / V 0.493 -> mesh S 0.156 / V 0.439; the Gaussian keeps S 0.439). That is TRELLIS' own behaviour, not a port bug - **ruled out by experiment**: decoding the *same* saved slat with the mesh decoder in fp16 vs fp32 gives identical S 0.156, preprocessing costs only 4 % saturation, and the pipeline call matches `run()` exactly. DIRECT never displays mesh colour: both its appearance paths decode `formats=["gaussian"]` (`demo.py:306`, `preprocess_example.py:320`) and the mesh is used once, for `return_types=["mask","normal"]` (`direct/geometry.py:109`). **So show the Gaussian, not the mesh.**
  `--fp32` works but is unusable end-to-end on the 16 GB iGPU: the models alone take 8.69 GB in fp32 (5.73 fp16) and the run dies mid-reconstruct. It is fine for decoder-only work (decode a saved `slat.pt`). It was also broken until 2026-09-23: `convert_to_fp32()` only re-casts parameters, while the models carry `self.dtype` (set once from `use_fp16`) and cast activations with it - without resetting `dtype`/`use_fp16` every matmul raises "mat1 and mat2 must have the same dtype".
- **Pose-controlled rendering** (`object_edit/render3d.py`, added 2026-09-23): DIRECT's 3D -> image step. In `demo/demo_utils.py` it is (1) viser `add_transform_controls` gizmo -> (2) `apply_gaussian_transform(gaussian, wxyz, position)`, a rigid (R,t) applied to the *representation* (splat centres + each splat's own rotation quaternion), not the camera -> (3) `get_fixed_view_matrix(camera.position)` + `utils3d.torch.intrinsics_from_fov_xy` -> (4) `GaussianRenderer.render(...)["color"]` -> (5) `postprocess_rendered_image` crops to the object bbox, expands 1.2x, pads square, resizes 512 = the condition image FLUX sees. `direct/geometry.py: render_normal_from_slat` does the same for a normal map via `MeshRenderer`; `preprocess_example.py` renders 6 canonical views to fit the input pose with VGGT.
  ```
  python -m object_edit.render3d --mesh outputs/image_to_3d/<stem>/mesh.glb --orbit 8
  python -m object_edit.render3d --mesh ... --yaw 40 --pitch 20 --kind normal --crop
  ```
  Camera math is DIRECT's verbatim (same `utils3d` calls, same `intrinsics_to_projection`); only the rasteriser is replaced, since both TRELLIS renderers are CUDA-only (`GaussianRenderer` -> diff-gaussian-rasterization, `MeshRenderer` -> nvdiffrast). The replacement is a z-buffered PyTorch triangle rasteriser: each face expanded over its own screen bbox (ragged, so the sub-pixel faces of a dense FlexiCubes mesh cost ~1 px each), edge-function test, scatter-min over depth. **No backface culling** - FlexiCubes winding is inconsistent, culling would hole the surface. Returns `color`/`normal`/`depth`/`mask` like `MeshRenderer.render`. `--self-test` checks occlusion order, barycentric interpolation (2e-7) and projection against a hand-computed pixel (0.1 px). Mesh only - the Gaussian splat path would need an EWA splatter.
- `object_edit/trellis_compat.py` makes that run without CUDA: pure-PyTorch stand-ins registered in `sys.modules` for **spconv** (only stride-1 *submanifold* conv is ever needed - every model-level `sp.SparseConv3d` is `(in, out, 3|1)` and down/upsampling is the already-pure-torch `SparseDownsample`/`SparseUpsample`) and **xformers** (`memory_efficient_attention` + `BlockDiagonalMask` -> `F.scaled_dot_product_attention`), plus `kaolin.utils.testing.check_tensor` for FlexiCubes and a `cuda`->XPU redirect for the hardcoded `device="cuda"` in `representations/`. Checkpoints store sparse-conv weights in spconv 2.x KRSC layout `[out_C, kD, kH, kW, in_C]`. `python -m object_edit.trellis_compat --self-test` checks the conv against `F.conv3d` and the attention against per-segment SDPA (agrees to ~1e-14).
  Not portable to CUDA-only extras: `to_glb` texture baking (nvdiffrast), the Gaussian/mesh renderers (diff-gaussian-rasterization) and DIRECT's own insertion half - so `mesh.glb` carries FlexiCubes' per-vertex colours and `preview.png` is a small software point splat.
- Gated on this account: `black-forest-labs/FLUX.1-*`, `stabilityai/stable-diffusion-2-*`, `briaai/RMBG-2.0` (mirrors exist: `second-state/FLUX.1-dev-GGUF`, `sd2-community/...`). RMBG-2.0 is TRELLIS' matting model -> use `--matte white` for subject crops on white, or `--mask`.
- iGPU "device" memory is carved from system RAM: never keep two large models resident.

# Web UI (server/ + web/, added 2026-09-21)
```
python -m uvicorn server.app:app --port 8000     # API + built UI (web/dist) at http://localhost:8000
cd web && npm run dev                            # dev UI on :5173, proxies /api and /files to :8000
```
- `server/app.py` FastAPI routes (`/api/uploads`, `/api/sam/proposals`, `/api/masks`, `/api/jobs`, `/files/...`); `server/gpu.py` one worker thread + priority queue that owns every model call (interactive SAM first, jobs never pre-empted); `server/sam_session.py` encodes an image once (`Sam3TrackerModel.get_image_embeddings`) and decodes box prompts against the cached embedding (`forward(image_embeddings=..., input_boxes=...)`, ~50-100 ms); the SAM model is unloaded before a job and reloaded lazily. `floor_edit.run_floor_edit(...)` and `object_edit.run(...)` are the entry points; `on_stage` callbacks drive progress.
- `web/src/BoxCanvas.tsx` owns display<->natural px mapping, box drag, tinted mask overlay and brush painting (RGBA mask canvas at natural size, exported as PNG; the server takes alpha > 127 as object). `ObjectEdit.tsx` is the step machine source -> mask -> (brush) -> target -> review -> running.
- Runtime files under `data/` (uploads, masks, jobs/<id>), git-ignored. Uploads are EXIF-transposed and capped at 2000 px so browser pixels == pipeline pixels.
